## 0. 心智模型：前端與後端是兩件事

| | 前端 | 後端 |
|---|---|---|
| 內容 | `index.html`、`js/`、`i18n/`、`compiled.css` 等根目錄檔案 | `firebase-functions/functions/src/` |
| 部署方式 | `git push origin main` → GitHub Pages 自動發佈 | `firebase deploy --only functions` |
| 生效時間 | 1～2 分鐘 | 數分鐘（依 function 數量） |
| 會自動嗎 | **會**（push 即部署） | **不會**（push 不會更新後端） |

⚠️ **最常見的錯誤：改了 Cloud Function 卻只 push，線上行為沒變。**
後端改動一定要另外 deploy。

## 2. 部署

### 建議做法：一鍵腳本

```bash
scripts/deploy.sh
```

行為：前端一定 push；後端只在 `firebase-functions/` 有改動時才 deploy。

```bash
scripts/deploy.sh --skip-backend    # 只推前端
scripts/deploy.sh --skip-frontend   # 只動後端
scripts/deploy.sh --force-backend   # 後端沒改也強制 deploy
```

### 手動做法

**前端**
```bash
git push origin main
# GitHub Pages 自動部署，1~2 分鐘後生效
```

**後端**
```bash
cd firebase-functions
firebase deploy --only functions --project wenhui-check-in-system
```

只部署特定 function（快很多，改動範圍明確時建議）：
```bash
firebase deploy --only functions:punch,functions:checkSession \
  --project wenhui-check-in-system
```

## 4. Rollback

### 前端
```bash
git revert <壞掉的 commit>
git push origin main
# GitHub Pages 1~2 分鐘後自動回到舊版
```
急件可直接 `git reset --hard <好的 commit> && git push --force origin main`，
但會改寫歷史，非緊急不要用。

### 後端
Cloud Functions **沒有一鍵回滾**，要用程式碼回退再重新部署：
```bash
git revert <壞掉的 commit>
cd firebase-functions
firebase deploy --only functions --project wenhui-check-in-system
```

若是**新加的** function 出問題，直接刪掉最快：
```bash
firebase functions:delete <functionName> --project wenhui-check-in-system
```

⚠️ **注意資料面不可逆**：若改動已寫壞 Firestore 資料（例如聚合欄位算錯），
回退程式碼不會自動修正既有文件，需要另外跑修補腳本
（可參考 `firebase-functions/scripts/backfill-attendance-monthly.js` 的寫法）。

## 5. 已知限制（部署時心裡有數）

- **後端 `day.hours` 不扣休息時段**：前端 `enrichDayWithLaborStats` 才補算扣除。
  `getCalendarSummary` / `getAttendanceDetails` 回傳的 `hours` 是 raw gross。
- **打卡冷卻只在前端**：重整頁面後冷卻歸零，後端目前無 60 秒去重。
- **Service Worker 快取**：使用者可能要重新整理才看得到新版前端。
- **薪資 Excel 尚缺**：住宿扣項、所得稅扣繳（外籍員工常見）。
  規劃見 [plans/薪資結算月報與匯出實作計畫.md](plans/薪資結算月報與匯出實作計畫.md) Phase M6。
- **假日判定依賴第三方 API**：`api.pin-yi.me` 掛掉會讓日別判斷退回「只看星期」，
  國定假日的薪資會算錯。
