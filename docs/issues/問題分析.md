## 🟠 中優先級

### 2.1 sessionToken 存在 localStorage（XSS 風險）

- **背景**：2026-04-14 已實施方案 B（改用 POST，token 不再經 URL 傳遞）。
- **剩餘風險**：token 仍寫入 `localStorage`，任何 XSS 漏洞都能被竊取。
- **目前狀態**：🟠 **阻塞條件已解除，可以動了**（2026-09-09 更新）
  - 原本的暫緩理由是「等 GAS 完全退場」——**GAS 已於 2026 年退場**，
    前端 `js/config.js` 移除 `apiUrl` 並鎖死走 Cloud Functions，
    舊程式碼封存於 [`docs/legacy/`](../legacy/)。前提條件已達成。
  - 尚未動工的原因改為工程成本：36 個 Cloud Functions 目前是 `onCall`，
    要改 `onRequest` 才能設 cookie。
- **未來方案**：
  - Cloud Functions 從 `onCall` 重寫成 `onRequest`
  - 後端發 httpOnly cookie + SameSite=None + Secure
  - 前端移除 `callApifetch` 帶 sessionToken 的邏輯，改 `credentials: include`
- **相關**：09-08 報告 B-H1（session 不可撤銷）已於 2026-09-08 補上 `logout` 端點，
  但 token 仍存 localStorage，本項不受影響。
- **位置**：[js/app.js](../../js/app.js)、[js/firestore-client.js](../../js/firestore-client.js)、`firebase-functions/functions/src/*`
- **預估工時**：16–24h

## 🟡 低優先級（技術債）

### 4.1 全域變數污染（state.js）

- **現況**：[js/state.js](../../js/state.js) 仍以全域 `var/let` 暴露大量狀態（`userId`, `currentMonthDate`, `currentLanguage`...）。
- **影響**：難以追蹤狀態變化、模組之間隱性耦合。
- **改善方向**：包成 `AppState` class 或 `Object.freeze` 命名空間。
  - 注意：`js/modules/state.js` 內已有一個無人呼叫的 `AppState`（09-08 報告 F-L12 列為死碼），
    要嘛接上去用、要嘛刪掉，不要放著。
- **預估工時**：4–6h（接觸面廣）

---

### 4.2 缺少統一 API 錯誤邊界

- **現況**：各模組直接 `await callApifetch(...)`，錯誤處理散落各處。
- **改善方向**：包一層 `callApiWithErrorHandling`，統一 toast/log/重試。
- **相關**：09-08 報告 U-H5（session 過期無全域攔截）、U-H3（API 無逾時）都會落在這一層，
  建議一起做。
- **預估工時**：2–3h

---

### 6.1 翻譯完整性檢查

- **現況**：[js/modules/i18n.js](../../js/modules/i18n.js) 載入後不會比對其他語言缺哪些鍵。
  `tests/i18n.test.js` 目前只測 `t()` 的行為，**沒有**做跨語系 key 差集檢查。
- **影響**：新增翻譯鍵時容易漏改其他 4 國語系，UI 直接顯示 raw key。
- **改善方向**：加一支測試 diff 五個語系（zh-TW / en-US / ja / vi / id）的 key set，缺漏即失敗。
- **相關**：09-08 報告另列「104 個翻譯 key 無人使用」，可一併寫成雙向檢查
  （缺漏 + 未使用）。
- **預估工時**：1–2h

---

### 8.2 類型安全（JSDoc / TypeScript）

- **現況**：純 JS，無型別註解；Cloud Functions 端也沒有 JSDoc。
- **改善方向**：先補關鍵模組（labor-hours、firestore-client、_helpers）的 JSDoc，未來視情況評估 TS。
  - `js/labor-hours.js` 的 JSDoc 已相對完整，可當範本。
- **預估工時**：分批進行

---

### 8.5 結構化日誌（Logger）

- **現況**：前端 `js/` 底下約 79 個 `console.log`，無等級控制、無遠端收集。
  集中在 `location.js`(14)、`punch/punch-flow.js`(12)、`admin.js`(11)、
  `modules/i18n.js`(9)、`punch/abnormal-records.js`(8)。
- **風險**：部分會印出 LINE userId 與整筆打卡紀錄（含 GPS 座標），
  見 09-08 報告 F-L4。正式環境的瀏覽器 console 任何人都打得開。
- **改善方向**：簡單 Logger 封裝（debug/info/warn/error），以 DEBUG flag 控制，
  正式環境只留 warn/error，且不印個資。
- **預估工時**：2h
- **狀態**：🔴 尚未處理（2026-09-09 清理未涵蓋此項，因需修改 `js/` 底下檔案）

### 9.1 前端設定硬編碼

- **現況**：[js/config.js](../../js/config.js) 寫死 `redirectUrl` 與 Firebase 專案設定。
- **更新（2026-09-09）**：原本描述的「寫死正式環境 GAS URL」**已不存在**——
  `apiUrl` 隨 GAS 退場移除，且刻意鎖死不提供 `?backend=gas` 降級開關（安全考量，勿還原）。
- **剩餘部分**：`redirectUrl` 與 Firebase config 仍是硬編碼。
  `getRedirectUrl()` 已能偵測 localhost 自動切換，實務上夠用；
  Firebase apiKey 屬公開資訊，但**應在 GCP 主控台加 HTTP referrer 限制**（09-08 報告 F-L11）。
- **優先級**：🟢 降級——目前不構成實際問題，僅保留 referrer 限制這項待辦。
- **預估工時**：0.5h（設 referrer 限制）

## ✅ 已解決（存查）

### 2.2 Session TTL 清理機制缺失 — **已完成**

- **實作**：[`cleanExpiredSessions.js`](../../firebase-functions/functions/src/cleanExpiredSessions.js)
  每天台北時間 03:00 批次刪除 `sessions` 與 `oneTimeTokens` 中 `expiredAt < now` 的文件。
- **狀態**：2026-04-27 實作完成；其後多次 `firebase deploy --only functions` 已涵蓋部署。
  可在 Firebase Console → Functions 確認 `cleanExpiredSessions` 的最近執行時間。
- **未來可選**：改用 Firestore TTL policy 取代（GCP 原生、零維護），設定後可移除本 function：
  ```bash
  gcloud firestore fields ttls update expiredAt \
    --collection-group=sessions --enable-ttl --database=default
  gcloud firestore fields ttls update expiredAt \
    --collection-group=oneTimeTokens --enable-ttl --database=default
  ```

### GAS 後端退場 — **已完成（2026）**

前端鎖死走 Cloud Functions，`js/config.js` 移除 `apiUrl` 與降級開關；
舊 GAS 程式碼移至 [`docs/legacy/`](../legacy/) 封存。
連帶解除了 2.1 的阻塞條件。
