## 1. 後端安全（Cloud Functions）

### 做對的地方（先講）
- Firestore rules 全鎖（`firestore.rules:7-9`），所有讀寫都走 Cloud Functions，授權集中一處。
- 33 個 function 中 30 個驗 session，12 個管理員端點都在後端查 `employees.dept === "管理員"`（`_helpers.js:192-199`），不信任前端傳的角色。
- 員工端 9 個可指定他人 id 的端點全部有 ownership 檢查或強制回自己 id。**未發現 IDOR。**
- 機密走 `defineSecret`，git 歷史掃描無硬編碼金鑰。
- OAuth state 後端產生、10 分鐘、交易式一次性消費。
- 審核狀態機只允許 `?` → `v/x`；未核准的補卡不計工時。

### 高
**B-H1　Session 不可撤銷**　`_helpers.js:70,149-150,365-373`、`index.js`（無 logout）、`js/app.js:227-232`
- 30 天固定有效、非滑動，沒有 logout / 撤銷 / 輪替端點。前端「登出」只清 localStorage。
- 情境：共用手機、遺失手機、或被 XSS 偷走 token，30 天內都可冒用；管理員 token 外洩 = 30 天內可改任何人出勤、核准、設薪資、讀全員 email/薪資。
- 修法：新增 `logout` action 刪 `sessions/{token}`；改滑動式 7 天閒置失效；管理員 session 更短。

### 中
**B-M1　`month` 只驗格式不驗範圍，無資料月份也寫聚合 doc**　`_helpers.js:210-212`、`_attendance.js:566-591`
- `isValidMonth` 接受 0001-01～9999-12；`records.length === 0` 仍 `tx.set`。任何登入員工可迴圈 12 萬個月份灌爆 `attendanceMonthly` 與帳單。
- 修法：限 2020-01～今日+1 月；空資料直接回空陣列不寫入。

**B-M2　後端無重複打卡防護**　`punch.js:110-128`
- 冷卻只在前端記憶體（重整即歸零）；curl 可秒寫上千筆。`deleteAttendance.js:50` 註解會誤導維護者以為後端有擋。
- 修法：寫入前查同 userId 最近一筆同 type，60 秒內拒絕；或以 `${userId}_${type}_${minuteBucket}` 為 doc id 做冪等。

**B-M3　無 rate limit、無 App Check；`getLoginUrl` 未驗證且每次寫一筆**　所有 `onCall`、`getLoginUrl.js:30-32`
- 匿名打 10 萬次 = 10 萬筆 `oauthStates`，隔天 03:00 才清。
- 修法：`enforceAppCheck: true`；`oauthStates` 改 Firestore TTL 政策。

**B-M4　redirect_uri 白名單用 `startsWith`，可被繞過**　`_helpers.js:46`
- `https://wenhuistage-ops.github.io.evil.com/` 與 `https://wenhuistage-ops.github.io@evil.com/` 都通過。目前靠 LINE 主控台的 callback 註冊擋住，但這層形同虛設。
- 修法：`new URL(url).origin === "https://wenhuistage-ops.github.io"`。

**B-M5　管理員寫入端點缺驗證**　`adjustPunchAsAdmin.js:57-62,87-89`、`updateAttendanceAsAdmin.js:73-78,95,117`、`punchWithoutLocation.js:33`
- `type` 無白名單、`datetime` 只驗 isNaN、`note` 未 clampText、`lat/lng` 可為 NaN、`timestamp` 無範圍。
- 後果：傳 `type: "請假"` + `audit: "v"` 可讓當日工時歸零；900KB note 撞 Firestore 1MiB 上限讓整月月曆 500；年份 9999 產生垃圾聚合。
- 修法：重用員工端已有的 `isValidPunchType`、`isReasonableAttendanceDate`、`clampText`、`validateCoordinates`。

### 低
- **B-L1**　OAuth state 未綁定用戶端；存下的 redirectUrl 沒被使用（`_helpers.js:439`、`getProfile.js:103-118`）。建議導入 PKCE。
- **B-L2**　`exchangeToken` 是死端點，`oneTimeTokens` 無人寫入；`getProfile` 回傳的 `sToken` 就是 30 天 token（`exchangeToken.js:28`、`_helpers.js:359-379`）。刪除或真正實作。
- **B-L3**　Session token 明文當 doc id（`_helpers.js:366-367`）。改存 sha256。
- **B-L4**　`deleteAttendance.js:69-71` 把整筆含 GPS 座標的 doc 印進 Cloud Logging；`checkYesterdayPunch.js:194,213,225` 逐人印姓名。只記 docId 與前 8 碼。
- **B-L5**　`getProfile.js:139-143` 把 LINE 原始錯誤 JSON 回給前端。固定回 `ERR_LINE_AUTH_FAILED`。
- **B-L6**　Session 快取跨容器 60 秒不失效（`_helpers.js:86-116`），降權後短暫仍有舊權限。
- **B-L7**　管理員可自審自批（`approveReview.js:26-40`、`adjustPunchAsAdmin.js:52,94`）。`targetUserId === 自己` 時拒絕。
- **B-L8**　待審清單以目標日期而非申請時間過濾，可產生永遠看不到的待審件（`getReviewRequest.js:57-61`）。
- **B-L9**　`.doc()` 拼接未做字元白名單，含 `/` 的 userId 直接 500（`getCalendarSummary.js:29-32`、`approveReview.js:17-20`）。`setEmployeeSalaryProfile.js:48-50` 已有正確寫法可複用。
- **B-L10**　地點名稱、休息時段字串無長度上限（`addLocation.js:18,29`、`setBreakTimes.js:43`）。
- **B-L11**　`submitLeave.js:76,84-86`：`type` 非白名單、`reason` 自由文字但扣薪規則靠它判斷。套用 `updateLeaveAsAdmin.js:26-29` 的 `LEAVE_KINDS`。
- **B-L12**　`cors: true` 允許任何來源。改成明確網域。
- **B-L13**　`firebase.json` predeploy lint 是 `echo 'no lint configured'`。加 ESLint。
- **B-L14**　id_token 只 base64 解碼未驗簽（`getProfile.js:67-83`），目前只用於顯示 email，無害但要標示「未驗證」。
- **B-L15**　`checkYesterdayPunch.js:208-209` 不過濾 `audit`，被退回的補卡也算「有打卡」。
- **B-L16**　`_attendance.js:32` `parseMonth` 接受 `\d{1,2}`，腳本 `--month=2026-13` 靜默算成 2027-01。
- **B-L17**　`_attendance.js:235-245` 同日同 HH:MM/type 第二筆被靜默丟棄，UI 無法刪除它。

## 2. 前端安全

### 做對的地方
- CSP `script-src` 無 `'unsafe-inline'`/`'unsafe-eval'`，index.html 零 inline script、零 `on*=`。
- 三個 CDN 資源 SRI 雜湊經實際下載比對全部正確；DOMPurify 自託管且與官方位元組一致。
- OAuth state 前端 + 後端雙驗；管理員 UI 每次回伺服器 `checkSession` 驗，`localStorage.userDept` 只當顯示快取。
- Service Worker 只攔同源 GET、不快取 OAuth 回跳、API 不經 SW，快取內沒有含 session 的回應。

### 高
**F-H1　員工「請假原因」未轉義直接寫入管理員請假統計卡片**　`js/admin.js:3944 → 4001 → 4033`
- 全專案唯一含使用者資料卻沒過 DOMPurify 的 innerHTML。前端用 `<select>` 但 API 任填（`make-up.js:608-615`），後端 `clampText` 只截長度不轉義。
- 情境：員工送 `<style>…</style>` 或釣魚 `<a>`，審核清單看起來只是怪文字，核准後統計卡片原樣渲染。CSP 擋 script，但 `style-src 'unsafe-inline'` 讓 CSS 注入、版面覆蓋、釣魚連結成立。
- 修法：共用 `escapeHtml()` 對所有 `${使用者欄位}` 轉義；再包 `DOMPurify.sanitize`。

**F-H2　DOMPurify 保留 class/data-*，員工可在管理員畫面植入真的會被綁定的按鈕**　`js/admin.js:419-425,542-604,1145-1196,4133-4170`
- 事件用 class 委派（`.admin-delete-record-btn`、`.approve-btn`），`data-doc-id` 直接取自 dataset。
- 情境：員工在 `adjustPunch.note` 放 `<button class="admin-delete-record-btn" data-doc-id="別人的打卡id">刪除</button>`，管理員看到多一顆「刪除」，確認框文字也是攻擊者的 dataset 組出來的，按下即刪任意出勤。
- 修法：同 F-H1 轉義；委派 handler 只認程式產生的節點（例如 `btn.closest('[data-actions-root]')`）。

### 中
- **F-M1**　登出只清 localStorage（`js/app.js:227-232`），同 B-H1。
- **F-M2**　`?action=in|out` 連結會在無確認下自動打卡（`js/punch/auto-punch.js:20-48`），且 `checkAutoPunch` 被呼叫兩次（`js/app.js:457,468`）。任何人把 `?action=out` 貼給同事，對方一開就被打下班。修法：加確認框；刪 `app.js:457` 那次呼叫。
- **F-M3**　打卡冷卻只在前端（同 B-M2）。
- **F-M4**　補卡日期限制只在前端（當月、不晚於今日），後端接受 2020-01-01～今天+400 天（`make-up.js:37-54` vs `_helpers.js:220-226`）。
- **F-M5**　CSP 以整個 `cdnjs.cloudflare.com` 為信任來源（已知 CSP-bypass gadget 寄存地）；`placehold.co` 只為兩個預設頭像。改路徑級白名單、頭像改本地。
- **F-M6**　薪資日別（國定/例假/休息）完全取決於第三方假日 API `api.pin-yi.me`，快取在可改寫的 localStorage（`holidays-client.js:20,47-54`、`labor-hours.js:232-234`）。API 錯或停擺 → Excel 薪資靜默算錯。改由後端提供或內建官方假日表交叉比對。

### 低
- **F-L1**　`(0, eval)(txt)` 仍在 `js/admin.js:1800-1816`（不在 docs 說的 weekly-chart.js），正式環境不執行且被 CSP 擋，但 `?_ensure=` 時間戳會污染 SW 快取。整段刪除。
- **F-L2**　14 處 innerHTML 未過 DOMPurify（目前只含常數/i18n，安全但無防護）。統一政策。
- **F-L3**　地點名稱未消毒塞進 Leaflet popup（`js/location.js:73-74`）。
- **F-L4**　console.log 印 LINE userId 與整筆紀錄（`abnormal-records.js:76`、`admin.js:40-43,316`、`ui.js:598,612`）；全站 81 個 console.log。
- **F-L5**　`navigator.userAgent` 被當打卡備註存進人資紀錄並顯示給管理員（`punch-flow.js:88,220`、`make-up.js:517,532,556`）。
- **F-L6**　z18 圖磚請求間接把員工位置（約 140m 解析度）告知 OpenStreetMap。
- **F-L7**　無 framebusting（meta CSP 不支援 `frame-ancestors`）。在 theme-init.js 加 `window.top !== window.self` 檢查。
- **F-L8**　`window.open(LINE_URL, '_blank')` 未加 `noopener`（`js/app.js:507`）。
- **F-L9**　無 `<meta name="referrer">`。
- **F-L10**　`res.user.picture || res.user.rate` 用不存在的欄位當頭像 fallback（`js/app.js:52,56`），日後若加 `rate`（時薪）會寫進 `<img src>`。
- **F-L11**　載入未使用的 Firestore SDK（`firestore-client.js:48,53`）；Firebase apiKey 應在 GCP 加 HTTP referrer 限制。
- **F-L12**　死碼：`js/modules/request-approval.js`（用 `prompt`，無人呼叫）、`js/modules/state.js` 的 AppState（無人呼叫）。
- **F-L13**　正式 UI 保留測試按鈕 `test-notification-btn`（`index.html:942`）、`test-api-btn`（`:1303`）。

## 3. 使用者體驗

### 做對的地方
- 定位權限引導彈窗依 iOS/Android/桌機分別說明、有「重新嘗試」、全走 i18n（`geolocation.js:228-306`）。
- 防重複打卡三層：60 秒冷卻 + 進行中 flag + 成功後立即追加到今日紀錄。
- 破壞性操作一律自製 `showConfirmDialog` 且標明是哪一筆；開關失敗自動回滾。
- 5 語系 616 個 key 完全同步，前端使用的 key 無缺漏。
- 補卡表單預填 08:00/18:00、病假證明軟提醒不強制、照片前端壓到 700KB。

### 高
**U-H1　月初依提醒回來補上月最後一天是死路**　`make-up.js:37-54`、`ui.js:772-785`、`checkYesterdayPunch.js:136`
- 提醒 → 切上月點昨天 → 填好送出才跳「不能選本月以前」，沒說該怎麼辦。舞台場次常在月底，這條路徑很常走到。
- 修法：下限改「今天往前 N 天」；月曆層就不顯示不可補的日期；`datetime-local` 加 `min/max`。

**U-H2　GPS 失敗訊息三語混雜、沒有下一步**　`geolocation.js:167-169`、`location.js:256`
- 越南員工看到「Không thể lấy vị trí: Timeout expired [code 3] (已重試 1 次)」。已有 `ERROR_GEOLOCATION_TIMEOUT/UNAVAILABLE/PERMISSION_DENIED` 5 語 key 卻只在 `location.js:233-245` 用到。
- 超出範圍、精確度差的訊息也沒有「請走近『{地點}』再試」這類可執行建議。
- 修法：依 `err.code` 映射到既有 key；訊息加一句動作。

**U-H3　打卡 API 無逾時，弱網下按鈕可卡「處理中…」最長 70 秒**　`firestore-client.js:107-108`、`punch-flow.js:58-60`
- 修法：`httpsCallable(fn, action, { timeout: 15000 })`，逾時走既有 `ERR_FIRESTORE_CALL_FAILED` 文案（已 5 語）。

**U-H4　所有 info 型通知都顯示成紅色錯誤**　`core.js:135-141`
- 只認 success/warning，其餘一律 `bg-red-500`。從 LINE 一鍵打卡第一眼是紅色「正在自動打卡…」；GPS 精確度提示紅色讓員工以為失敗而再按。
- 修法：補 `info` 樣式。

**U-H5　Session 使用中過期沒有全域攔截，介面默默失效**　`firestore-client.js:79-125`、`core.js:52-60`
- 打卡紅 toast、月曆停在「正在載入…」、異常清單變整月異常，畫面仍顯示已登入。文案「Session 已過期」外籍員工看不懂。
- 修法：`callApifetch` 統一攔截 `ERR_SESSION_EXPIRED/INVALID` → 清 token、顯示「請重新登入」。

**U-H6　LINE 提醒永遠中文；請假的人也被催**　`js/app.js:411`（`languag` 拼錯）、`getProfile.js`（不讀語言）、`_helpers.js:350`（`preferredLanguage: ""` 之後無人更新）、`checkYesterdayPunch.js:208-209`
- 六語文案形同虛設；有請假紀錄的日子判成「漏打上班卡」；假日/休息日也發（每週一早上全員收到）。
- 修法：`getProfile/checkSession` 存 `currentLang`；提醒略過請假日、國定假日、例假日。

**U-H7　Font Awesome 從未載入，全站圖示空白**　`index.html`（無載入）、`compiled.css`（0 條 `.fas`）、37 處 `<i class="fas …">`
- 修法：改用 inline SVG 或 emoji（不要為此再加一個 CDN）。

### 中
- **U-M1**　審核結果不通知員工；「員工報表」路徑退回不問原因（`approveReview.js`/`rejectReview.js` 無 push；`admin.js:4194-4195` vs `1272-1277`）。
- **U-M2**　凌晨 00:00–08:00 點月曆「今天」沒反應（`ui.js:416-419` 用 `new Date('YYYY-MM-DD')` 以 UTC 解析）。`ui.js:780-781` 已有正確寫法。
- **U-M3**　「補全日」拆兩次 API，下班失敗重送會重複上班申請（`make-up.js:509-546`）。
- **U-M4**　假別以翻譯後文字存進資料庫（`make-up.js:375-377,412-415`），同一種病假存成「病假 / Nghỉ ốm / Izin Sakit」，統計拆成多類。改固定代碼。
- **U-M5**　打卡主按鈕被 256px 地圖擠出手機首屏（`index.html:421-446`）；按錯上/下班無確認（`app.js:235-236`）。
- **U-M6**　已送出申請的日子仍以紅字列在異常紀錄，「審核中」硬編中文（`abnormal-records.js:49-56,257,264-268`）。
- **U-M7**　病假證明 `capture="environment"` 在 Android 強制開相機，選不到相簿（`make-up.js:268`）。拿掉 `capture`。
