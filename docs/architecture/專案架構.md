# 專案架構分析

## 📋 項目概述

**0riginAttendance-System** 是一個開源的考勤管理系統。員工用 **LINE 帳號登入**、以手機 **GPS 定位打卡**，
紀錄即時寫入 **Cloud Firestore**；管理員可線上審核補卡與請假、檢視勞基法分段工時並匯出薪資 Excel。

- **專案名稱**：attendance-system
- **版本**：1.0.0
- **授權**：GPL-2.0-or-later
- **作者**：0J (Lin Jie / 0rigin1856)
- **正式站台**：<https://wenhuistage-ops.github.io/>
- **Firebase 專案**：`wenhui-check-in-system`（區域 `asia-southeast1`）

> **架構沿革**：2026 年之前的後端是 Google Apps Script + Google 試算表，現已完全停用。
> 前端已鎖死走 Cloud Functions（`js/config.js` 移除 `apiUrl`、拿掉 `?backend=gas` 降級開關），
> 舊程式碼僅供查閱，見 [`docs/legacy/`](../legacy/)。

```
┌─────────────────────────────────────────────────────────────────┐
│                    FRONTEND（純靜態，無 build step）              │
│   index.html + js/*.js + compiled.css                           │
│   GitHub Pages 直接提供根目錄檔案                                 │
└────────────────────────────┬────────────────────────────────────┘
                             │ httpsCallable（Firebase SDK，走 CDN ES module）
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│              Firebase Cloud Functions（asia-southeast1）         │
│    30 餘個 onCall / 排程 function ── 全部業務邏輯與授權集中於此    │
└────────────────────────────┬────────────────────────────────────┘
                             │ Firebase Admin SDK
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                        Cloud Firestore                           │
│   employees / attendance / attendanceMonthly / sessions /        │
│   locations / settings / oauthStates / reviewRequests …          │
│   firestore.rules 全鎖：用戶端不可直接讀寫                        │
└─────────────────────────────────────────────────────────────────┘
              ▲                                    ▲
              │ OAuth 2.0                          │ Messaging API（推播）
       ┌──────┴───────┐                    ┌───────┴────────┐
       │  LINE Login  │                    │  LINE 官方帳號  │
       └──────────────┘                    └────────────────┘
```

**關鍵設計**：Firestore 對用戶端完全封閉，所有讀寫都必須經過 Cloud Functions，
授權檢查因此集中在一處（`_helpers.js`），不信任前端傳來的角色。

## 📌 核心功能模塊

### 1. 認證系統（Authentication）
- **技術**：LINE Login OAuth 2.0
- **流程**：
  1. 前端呼叫 `getLoginUrl`，後端產生 `state`（10 分鐘有效、交易式一次性消費）並回傳授權 URL
  2. 使用者在 LINE 授權後帶 `code` 回跳
  3. 前端呼叫 `getProfile`，後端與 LINE 交換 token、建立 `sessions/{token}` 文件
  4. 前端把 session token 存入 `localStorage`
  5. 後續每次 API 呼叫都帶 token，後端 `checkSession` 驗證
- **登出**：呼叫 `logout` 端點刪除後端 session，再清 `localStorage`
- **已知取捨**：session TTL 固定 30 天（非滑動）；跨容器快取最多 60 秒才失效

### 2. 定位打卡系統（GPS Punch Clock）
- **檔案**：`js/punch/punch-flow.js`、`js/punch/geolocation.js`、`js/location.js`
- **功能**：
  - `navigator.geolocation` 取座標（高精確度模式 + 自動重試 + 精確度品質評估）
  - 比對打卡地點座標與允許半徑
  - 防重複：60 秒冷卻 + 進行中 flag + 成功後樂觀更新今日紀錄
  - 無定位情境走 `punchWithoutLocation`

### 3. 補卡與請假審核
- 員工提交補打卡 / 請假（可附病假證明照片，前端壓縮至 700KB）
- 審核狀態機只允許 `?` → `v`／`x`；**未核准的補卡不計入工時**
- 管理員可代為補卡（`adjustPunchAsAdmin`）

### 4. 勞基法工時與薪資（`js/labor-hours.js`）
- 日別分四類：`workday`／`rest`（休息日）／`public`（國定假日）／`regular`（例假日）
- 分段時數：平日 normal/ot1/ot2、休息日三段、國定 base/ot1/ot2、例假 base/comp/ot
- 等價時數（各段 × 倍率）用於估算工資；另計違法工時（每日超過 12 小時）
- 月薪換時薪 ÷240、勞保投保級距推算、勞健保與勞退自付額
- **規則來源**：[../rules/薪資與加班計算規則整理.md](../rules/薪資與加班計算規則整理.md)
- **測試**：`tests/labor-hours.test.js`（行為測試；改動計算邏輯前先跑 `npm test`）

### 5. 管理員後台（`js/admin.js`）
- 員工設定：管理員權限、帳號啟用、薪資與勞保級距、打卡政策
- 打卡管理：新增／編輯地點（地圖選位 + 半徑）、公司休息時段
- 表單審核：全公司待審清單、批准／拒絕
- 員工報表：KPI、分段工時、週工時圖、月曆、Excel 匯出
- **權限**：每次進入都回伺服器 `checkSession` 驗；`localStorage.userDept` 只當顯示快取

### 6. 多國語系（i18n）
- **支援**：繁體中文、英文、日文、越南文、印尼文（5 語）
- 靜態內容用 `data-i18n` 標籤，動態內容用 `t()` 函式
- 使用者選的語言會同步到後端 `employees.preferredLanguage`，LINE 推播依此發送

### 7. 通知與排程
- 員工提交申請 → LINE 通知管理員
- 每日排程：漏打卡提醒（略過已請假/休假的日子）、虛擬打卡、清除過期 session
- 詳見 [異步通知系統.md](./異步通知系統.md)

## 🔄 請求流程

### 打卡流程
```
1. 使用者點「上班打卡」
   ↓
2. js/punch/geolocation.js 取得 GPS 座標（含重試與精確度檢查）
   ↓
3. 前端比對是否落在允許的打卡地點範圍內
   ↓
4. js/firestore-client.js → callApifetch({ action: 'punch', ... })
   ↓
5. Cloud Function punch.js：驗 session → 驗座標 → 寫入 Firestore attendance
   ↓
6. 回傳結果，前端顯示通知並把新紀錄追加到「今日打卡紀錄」
```

### 認證流程
```
1. 前端檢查 localStorage 是否有 sessionToken
   ↓
2. 有 → 呼叫 checkSession 驗證；無效則回登入畫面
   ↓
3. 無 → 呼叫 getLoginUrl，導向 LINE 授權頁
   ↓
4. 使用者授權後帶 code 回跳，前端呼叫 getProfile
   ↓
5. 後端與 LINE 交換 token、建立 sessions/{token}，回傳 session token
   ↓
6. 前端存入 localStorage，後續請求皆攜帶
```

## 🔐 安全與權限機制

### 現有機制
- `firestore.rules` **全鎖**：所有讀寫都必須經 Cloud Functions
- 絕大多數 function 都驗 session；管理員端點在後端查 `employees.dept === "管理員"`
- 員工端可指定他人 id 的端點皆有 ownership 檢查或強制回自己 id（未發現 IDOR）
- OAuth state 後端產生、10 分鐘有效、交易式一次性消費
- 機密走 `defineSecret`，不進 git
- 前端 CSP 無 `unsafe-inline`／`unsafe-eval`；使用者可控文字一律 `escapeHtml()` + DOMPurify

### 已知問題（詳見 09-08 檢查報告）
- session TTL 固定 30 天、非滑動；跨容器快取 60 秒才失效
- 後端無打卡去重、無 rate limit、無 App Check
- session token 以明文當 doc id，且存在前端 `localStorage`
- 部分管理員寫入端點的輸入驗證仍待補強

## 📈 擴展方向

1. **後端防濫用** — rate limit、App Check、打卡 60 秒去重
2. **Session 強化** — 滑動式 TTL、token 存 sha256、管理員 session 更短
3. **假日資料自主化** — 目前依賴第三方假日 API，改由後端提供或內建官方假日表
4. **權限細分** — 部門主管、HR 等角色
5. **結構化日誌** — 前端 console.log 收斂成有等級的 Logger
